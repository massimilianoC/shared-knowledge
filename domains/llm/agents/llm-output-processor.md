# Agent: LLM Output Processor

## Role
Specialized agent for receiving raw output from any LLM and returning
structured, validated, and normalized JSON — automatically handling
known model bugs without propagating errors to the application.

## Included skills
- [llm-json-parsing](../skills/output/llm-json-parsing.md) — full 5-stage parsing pipeline
- [llm-output-repair](../skills/output/llm-output-repair.md) — individual repair strategies

## When to use this agent

- Pipelines that consume structured JSON produced by LLMs
- Multi-model systems where several LLMs run in production at the same time
- Cases where the model may truncate the response because of `max_tokens`
- Outputs where HTML, CSS, or JS is embedded inside the JSON

## When NOT to use this agent

- Free-form text output that is not JSON — no parser is needed
- JSON generated by a controlled system rather than an LLM — the known model bugs do not apply
- Simple JSON schemas with no embedded HTML — the scoring logic may need recalibration or may be unnecessary
- Systems that already validate structure before parsing with a schema library such as Zod — integrate the repair logic there instead

## Recommended system prompt
```
You are an LLM output processor. You receive raw text from a model and must:
1. Extract valid JSON by applying repair strategies in order
2. Validate the structure against the expected schema
3. Normalize the fields (HTML, CSS, JS) before returning the result
4. Always return { result: object | null, valid: boolean, repairsApplied: string[] }

Never propagate exceptions — return { result: null, valid: false } if the failure is unrecoverable.
```

## Required context
- The expected JSON schema for post-parse validation
- `hasHtmlArtifacts: boolean` — enables HTML normalization
- `maxTokensLimit: number` — if set, enables truncation repair logic

## Behavior by model
| Model | Common bug | Active repair |
|---|---|---|
| gemma, phi | Premature `"` termination | mandatory triple-pass |
| qwen, mistral | Double-encoded HTML | `unescapeDoubleEncodedHtml` |
| Hunyuan-A13B | Stray `>",` token | `repairStrayGtBetweenFields` |
| All models | Markdown fences, `max_tokens` truncation | fence stripping + `repairTruncatedJson` |

## Guaranteed output
```ts
{
  result: ParsedSchema | null,   // null only if recovery is impossible
  valid: boolean,                // false if invasive repairs were needed
  repairsApplied: string[]       // list of applied repairs for logging and monitoring
}
```

## Known limitations
- `repairTruncatedJson` returns a partial result — the last field may still be cut off
- `jsonrepair` as a last resort can introduce unwanted transformations — monitor it in production
- The scoring logic is tuned for HTML-heavy output — adapt `scoreResult()` for other schemas
