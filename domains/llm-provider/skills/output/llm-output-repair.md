# Skill: LLM Output Repair (State Machine)

## Description
Implements repair functions for malformed JSON strings produced by LLMs.
The core pattern is a shared **`inString + escaped` state machine** used by all repair functions —
never rely on global regex replacements over raw JSON.

## Expected inputs
- `input: string` — a raw or partially malformed JSON string generated by an LLM
- The repair strategy to apply, chosen based on the known bug pattern

## Produced outputs
- `string` — a repaired string that is safe to pass to `JSON.parse()` or at least closer to a valid approximation
- `repair*` functions **never throw exceptions** — in the worst case they return the original input unchanged

## Common pitfalls to avoid

- ❌ Global regex across the entire JSON string → this also modifies nested string values such as HTML with `\n`

  ```ts
  // WRONG
  json.replace(/\n/g, "\\n")
  // CORRECT: use a state machine that tracks inString
  ```

- ❌ `repairPrematureStringTermination` without `":"` among the valid terminators → every JSON key remains “open” and corrupts the whole document
- ❌ Applying `repairTruncatedJson` without a later score comparison → a truncated JSON may beat a complete one
- ❌ Stopping after a single repair strategy → some model patterns require a triple-pass sequence
- ❌ Using `jsonrepair` as the first choice → it may introduce undesirable changes and should remain a last resort

## Steps / Procedure

### Base pattern - the state machine used by every repair function

```ts
let inString = false, escaped = false;
for (let i = 0; i < input.length; i++) {
    const ch = input[i];
    if (!inString) {
        if (ch === '"') inString = true;
        out += ch;
        continue;
    }
    if (escaped) { escaped = false; /* process ch here */ continue; }
    if (ch === "\\") { escaped = true; out += ch; continue; }
    if (ch === '"') { inString = false; out += ch; continue; }
    // → we are inside a string and not in escape mode: apply repair logic here
}
```

## Available repair functions

### `repairInvalidJsonEscapes(input)`
Fixes:
- Invalid escape sequences such as `\>` or `\ ` by converting them to `\\` + char
- Literal control characters inside strings, such as real newlines or tabs, converting them to `\\n`, `\\r`, or `\\t`

### `repairPrematureStringTermination(input)`
Fixes an unescaped `"` inside a string when it is not a legitimate closing quote.

The function performs lookahead after each `"` inside a string: if the next non-whitespace character is `,`, `}`, `]`, `:`, or EOF, it is considered a valid closing quote. Otherwise it should be escaped as `\"`.

**Critical:** include `":"` among valid terminators — otherwise every JSON key becomes corrupted.

### `repairTruncatedJson(input)`
Fixes LLM responses truncated by `max_tokens`.

Track open `{` and `[` symbols with a stack. At the end, close the string if necessary, then close the remaining stack in reverse order.

### `repairStrayGtBetweenFields(input)`
Fixes the stray `>",` token pattern seen between JSON fields in some Hunyuan-A13B outputs.

If `>` appears outside a string and the next significant character is `"`, treat it as noise and skip it.

### `extractFirstJsonObject(text)`
Extracts the first valid JSON object from mixed text.

It must use brace-depth tracking with the `inString + escaped` state machine and return `text.slice(start, closeIndex + 1)` or `null`.

## Contract rules
- `repair*` functions never throw exceptions — they always return a string, even if unchanged
- The order of application matters: go from the least invasive strategy to the most invasive one
- The triple-pass sequence (`repairInvalidJsonEscapes → repairPrematureStringTermination → repairInvalidJsonEscapes`) is required for Gemma and Phi-like patterns where one pass is not enough
