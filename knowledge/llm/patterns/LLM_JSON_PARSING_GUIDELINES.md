## The problem

LLM models occasionally produce JSON that fails `JSON.parse()` for recurring reasons:

- Markdown fences such as `````json ... ````` around the output
- Unescaped control characters inside strings, such as literal `\n`, `\r`, or `\t`
- Invalid escape sequences such as `\>` or `\ ` that are not legal JSON
- Premature string termination: a `"` that is not preceded by `\` and is not in a valid closing position
- Output truncated by `max_tokens`, leaving objects or arrays unclosed
- Double-encoded HTML such as `lang=\"it\"` instead of `lang="it"`
- Malformed HTML tags in HTML fields, such as `<h11>` or `</>`
- Empty strings or `<style>`/`<script>` wrappers in CSS and JS fields
- Stray tokens between JSON fields, such as `>",` in some Hunyuan outputs

---

## Overall architecture

```
rawLlmOutput
    │
    ▼
[1] Pre-parse cleanup (fence stripping, pre-repair)
    │
    ▼
[2] Multiple candidate generation (stripped, fenced, extracted, pre-repaired...)
    │
    ▼
[3] For each candidate → repair strategy chain
    │   ├─ Direct JSON.parse
    │   ├─ repairInvalidJsonEscapes
    │   ├─ triple-pass (escape + premature-termination + escape)
    │   ├─ repairTruncatedJson
    │   └─ jsonrepair (last resort)
    │
    ▼
[4] Select the highest-scoring result
    │
    ▼
[5] Post-parse normalization (HTML, CSS/JS, duplicate fields)
    │
    ▼
Validated canonical result
```

## Phase 1 — Pre-parse cleanup

### 1.1 Strip Markdown fences

Remove delimiters such as `````json ... ````` using string operations, which are more robust than regex alone when the content is large:

```ts
let stripped = trimmed;
if (stripped.startsWith("```")) {
    stripped = stripped.replace(/^```(?:json)?\s*\n?/i, "");
    const lastFence = stripped.lastIndexOf("```");
    if (lastFence > 0) stripped = stripped.slice(0, lastFence).trim();
}
// Regex fallback for fences embedded in the text
const fenceMatch = trimmed.match(/```(?:json)?\s*([\s\S]*?)```/is);
```

**Rule:** always apply this before any other repair step. Never rely on `JSON.parse()` over the raw response.

### 1.2 Apply pre-repair before extraction

Some models, such as Gemma, terminate a string too early with an unescaped `"`. That makes `extractFirstJsonObject` count braces inside the HTML incorrectly and return a truncated object.

Solution: apply escape repair and premature-termination repair **before** extracting the first object:

```ts
const preRepaired = repairInvalidJsonEscapes(
    repairPrematureStringTermination(repairInvalidJsonEscapes(trimmed))
);
```

## Phase 2 — Candidate extraction

Generate multiple candidate versions of the same input and deduplicate them:

```ts
const rawCandidates = [
    stripped !== trimmed ? stripped : null,          // fence-stripped
    fenceMatch?.[1]?.trim() ?? null,                 // regex-fence
    extractFirstJsonObject(trimmed),                 // brace-scan on raw text
    extractFirstJsonObject(preRepaired),             // brace-scan on pre-repaired text
    extractFirstJsonObject(stripped),                // brace-scan on stripped text
    gtRepaired !== source ? gtRepaired : null,       // stray-gt repaired
    gtRepaired !== source ? extractFirstJsonObject(gtRepaired) : null,
];
// Order-preserving deduplication
const seen = new Set<string>();
const candidates = rawCandidates.filter(c => c && !seen.has(c) && seen.add(c));
```

### `extractFirstJsonObject` — brace-depth state machine

```ts
function extractFirstJsonObject(text: string): string | null {
    const start = text.indexOf("{");
    if (start < 0) return null;
    let depth = 0, inString = false, escaped = false;
    for (let i = start; i < text.length; i++) {
        const ch = text[i];
        if (inString) {
            if (escaped) { escaped = false; }
            else if (ch === "\\") { escaped = true; }
            else if (ch === '"') { inString = false; }
            continue;
        }
        if (ch === '"') { inString = true; continue; }
        if (ch === "{") depth++;
        if (ch === "}") { depth--; if (depth === 0) return text.slice(start, i + 1); }
    }
    return null;
}
```

**Critical rule:** extraction must use a state machine that respects `inString + escaped`. Never use `indexOf("{")` or `lastIndexOf("}")` without tracking string boundaries — every `{` inside HTML would incorrectly count toward depth.

## Phase 3 — Repair strategy chain

Apply strategies from the least invasive to the most invasive. Stop at the first success for each candidate, then compare all successful results by score.

### Strategy 1 — Direct parse

```ts
JSON.parse(candidate)
```

### Strategy 2 — `repairInvalidJsonEscapes`

This fixes two classes of problems inside JSON strings:

**a) Invalid escape sequences** such as `\>` or `\ `:
```ts
// If the character after \ is not a valid JSON escape (\", \\, \/, \b, \f, \n, \r, \t, \u)
// convert it to \\ + char so the backslash becomes literal
out += "\\\\";
out += ch;
```

**b) Unescaped control characters** such as real newlines and tabs:
```ts
if (code === 0x0a) { out += "\\n"; continue; }  // newline
if (code === 0x0d) { out += "\\r"; continue; }  // carriage return
if (code === 0x09) { out += "\\t"; continue; }  // tab
```

Base state-machine pattern shared by all repair functions:
```ts
let inString = false, escaped = false;
for (let i = 0; i < input.length; i++) {
    const ch = input[i];
    if (!inString) {
        if (ch === '"') inString = true;
        out += ch;
        continue;
    }
    if (escaped) { escaped = false; /* process ch */ continue; }
    if (ch === "\\") { escaped = true; out += ch; continue; }
    if (ch === '"') { inString = false; out += ch; continue; }
    // → we are inside a string and not in escape mode
}
```

### Strategy 3 — Triple-pass (Gemma-like pattern)

```ts
repairInvalidJsonEscapes(
    repairPrematureStringTermination(
        repairInvalidJsonEscapes(candidate)
    )
)
```

**Why triple-pass:** some models emit correct `\"` sequences when opening HTML attributes but later close them with an unescaped `"`. The first `repairInvalidJsonEscapes` pass does not touch quotes, so `repairPrematureStringTermination` must detect the premature closing quote, followed by another escape-repair pass.

### `repairPrematureStringTermination`

Logic: when a `"` appears inside a string, perform lookahead skipping whitespace and verify whether the next character is a valid JSON terminator:

```ts
if (ch === '"') {
    let j = i + 1;
    while (j < input.length && /\s/.test(input[j])) j++;
    const nextCh = j < input.length ? input[j] : "";
    // ":" is required for JSON keys — without it every key looks like part of the string
    if (nextCh === "," || nextCh === "}" || nextCh === "]" || nextCh === ":" || nextCh === "") {
        out += '"';
        inString = false;
    } else {
        out += '\\"';  // premature closing quote: escape it
    }
    continue;
}
```

**Critical pitfall:** without `":"` among the valid terminators, **every JSON key** such as `"key":` is interpreted as a premature closing quote and the entire document becomes corrupted.

### Strategy 4 — `repairTruncatedJson`

Use this when the model hits the `max_tokens` limit and the response ends in the middle of a string or with open objects or arrays.

```ts
function repairTruncatedJson(input: string): string {
    const stack: ("{" | "[")[] = [];
    let inString = false, escaped = false;
    // ... scan to track open braces and brackets ...
    let suffix = "";
    if (inString) suffix += '"';           // close the open string
    for (let i = stack.length - 1; i >= 0; i--)
        suffix += stack[i] === "{" ? "}" : "]";  // close in reverse order
    return input + suffix;
}
```

**Note:** the result is still partial JSON — the final field may remain truncated. That is why score-based selection is needed to prefer complete results.

### Strategy 5 — `jsonrepair` (library)

```ts
import { jsonrepair } from "jsonrepair";
JSON.parse(jsonrepair(candidate));
```

This is the last resort. It can recover unexpected patterns, but it may also introduce unwanted transformations. Use it only if the earlier strategies fail.

### Additional repair — `repairStrayGtBetweenFields` (Hunyuan-A13B)

Some models emit a stray `>",` token between JSON fields, usually as a leftover `>` escaping out of the HTML string:

```
"html": "...</html>",
>"`,             ← STRAY TOKEN
"css": "..."
```

Solution: detect `>` outside a string, optionally followed by `"` and `,`, verify that the next significant character is `"` starting a new field, and skip the stray sequence:

```ts
if (ch === ">") {
    let j = i + 1;
    if (input[j] === '"') j++;
    if (input[j] === ',') j++;
    // skip whitespace
    let k = j;
    while (k < input.length && /\s/.test(input[k])) k++;
    if (input[k] === '"') {
        i = j - 1;  // skip the stray token
        continue;
    }
    out += ch;
}
```

## Phase 4 — Selecting the best result

When multiple candidates parse successfully, choose the one with the **highest score**, not the first one that works. This prevents a degraded candidate repaired by `repairTruncatedJson` from beating a more complete direct parse.

### Scoring function

```ts
function scoreResult(r: ParsedResult): number {
    let score = 0;
    const html = r.artifacts.html;
    score += Math.min(html.length, 50000) / 100;    // more HTML = better
    if (/<!doctype\s+html/i.test(html)) score += 100;  // complete document
    else if (/<html\b/i.test(html)) score += 80;
    if (/<\/html>/i.test(html)) score += 60;           // properly closed
    if (/<head\b/i.test(html)) score += 20;
    if (/<body\b/i.test(html)) score += 20;
    if (r.chat.summary.length > 10) score += 20;
    if (r.chat.bullets.length > 0) score += 10;
    if (r.artifacts.css.length > 50) score += 15;
    if (r.artifacts.js.length > 0) score += 3;
    return score;
}
```

**Principle:** a truncated parse almost always has shorter HTML and misses `</html>`, so it naturally scores lower and gets discarded if a complete parse exists.

## Phase 5 — Post-parse normalization

### 5.1 `unescapeDoubleEncodedHtml`

Some models double-encode HTML attributes in JSON, such as `lang=\"it\"`, leaving the HTML value with escaped quotes instead of normal ones:

```ts
function unescapeDoubleEncodedHtml(html: string): string {
    if (!html.includes('=\\"')) return html;  // fast path
    return html
        .replace(/\\"/g, '"')
        .replace(/\\n/g, '\n')
        .replace(/\\r/g, '\r')
        .replace(/\\t/g, '\t');
}
```

**Rule:** apply this only when the `=\"` marker is present so that normal HTML is not modified unnecessarily.

### 5.2 `normalizeHtmlArtifact`

Fix malformed markup after parsing:

```ts
function normalizeHtmlArtifact(html: string): string {
    if (!html) return html;
    return html
        // Double-digit heading tags: <h11> → <h1>, </h33> → </h3>
        .replace(/<(\/?)h(\d)\2>/gi, "<$1h$2>")
        // Empty closing tags </> are not standard and should be removed
        .replace(/<\/>/g, "");
}
```

### 5.3 `normalizeArtifactCssJs`

Some models wrap CSS or JS inside tags despite the prompt instructions:

```ts
function normalizeArtifactCssJs(content: string, kind: "css" | "js"): string {
    const trimmed = content.trim();
    if (!trimmed) return "";
    if (kind === "css") {
        const match = trimmed.match(/^<style[^>]*>([\s\S]*?)<\/style>$/i);
        return (match?.[1] ?? trimmed).trim();
    }
    const match = trimmed.match(/^<script[^>]*>([\s\S]*?)<\/script>$/i);
    return (match?.[1] ?? trimmed).trim();
}
```

### 5.4 Fallback: extract CSS and JS from HTML

When `artifacts.css` and `artifacts.js` are empty but the model inserted everything inline in the HTML:

```ts
function extractArtifactsFromHtml(html: string): { css: string; js: string } {
    const styleMatch = html.match(/<style[^>]*>([\s\S]*?)<\/style>/i);
    const css = styleMatch?.[1]?.trim() ?? "";
    // Only scripts without src= so external CDNs are excluded
    const scriptMatch = html.match(/<script(?![^>]*\bsrc\b)[^>]*>([\s\S]*?)<\/script>/i);
    const js = scriptMatch?.[1]?.trim() ?? "";
    return { css, js };
}
```

**Rule:** use this fallback only if the field is still empty after `normalizeArtifactCssJs`.

## Structural field validation

After parsing, validate every optional field explicitly before accepting it:

```ts
function extractFocusPatch(parsed: Partial<LlmResponse>): FocusPatch | undefined {
    const fp = parsed.focusPatch;
    if (!fp) return undefined;
    // Enum check
    if (!["html", "css", "js"].includes(fp.targetType)) return undefined;
    // Optional field: if present it must be a non-empty string
    if (fp.anchor !== undefined && (typeof fp.anchor !== "string" || !fp.anchor.trim())) return undefined;
    // Required field: must be a non-empty string
    if (typeof fp.replacement !== "string" || !fp.replacement.trim()) return undefined;
    return fp;
}
```

**Principles:**
- Distinguish clearly between **optional** and **required** fields
- Use `trim()` to reject whitespace-only strings
- Enum checks must be explicit at runtime
- Return `undefined`, not `null`, for missing optional fields

### Canonical assembly with defaults

```ts
function assembleResult(parsed: Partial<LlmResponse>): LlmResponse | null {
    if (!parsed?.chat || !parsed?.artifacts) return null;
    return {
        chat: {
            summary: String(parsed.chat.summary ?? ""),
            bullets: Array.isArray(parsed.chat.bullets) ? parsed.chat.bullets.map(String) : [],
            nextActions: Array.isArray(parsed.chat.nextActions) ? parsed.chat.nextActions.map(String) : [],
        },
        artifacts: { html: htmlStr, css: cssStr, js: jsStr },
        focusPatch: extractFocusPatch(parsed),
    };
}
```

**Rules:**
- Use `String(value ?? "")` for required string fields — never assume a value is already a string
- Use `Array.isArray(arr) ? arr.map(String) : []` for arrays — never assume element types
- Centralize assembly in a single function instead of duplicating it in every try/catch branch

## Naming conventions

| Pattern | Snake_case | camelCase | Meaning |
|---|---|---|---|
| Repair function | — | `repairXxx` | Transforms a string without changing shared state |
| Normalization function | — | `normalizeXxx` | Cleans or standardizes an already parsed value |
| Extraction function | — | `extractXxx` | Pulls a subset from a larger value |
| Field validation function | — | `extractXxx` | Validates and returns the field or `undefined` |
| Assembly function | — | `assembleXxx` | Builds the final canonical result |
| Scoring function | — | `scoreXxx` | Computes the qualitative score of a result |
| Public parsing function | — | `tryParseXxx` | Public entry point returning `{ result, valid }` |

**Naming rules:**
- `repair*` should never throw and should always return a string
- `try*` should catch exceptions internally and return `null` or `{ valid: false }`
- `assemble*` should return `null` when required fields are missing
- Repair names should describe **what they fix**, not the model that caused the bug

## Common pitfalls

### ❌ Repair logic that does not respect string boundaries

```ts
// WRONG: global regex on the raw JSON string also changes HTML values
json.replace(/\n/g, "\\n")

// CORRECT: use a state machine that tracks inString + escaped
```

### ❌ `repairPrematureStringTermination` without the `":"` case

```ts
// WRONG: missing ":" means every JSON key stays open
if (nextCh === "," || nextCh === "}" || nextCh === "]" || nextCh === "") {

// CORRECT
if (nextCh === "," || nextCh === "}" || nextCh === "]" || nextCh === ":" || nextCh === "") {
```

### ❌ Returning the first successful parse instead of the best one

```ts
// WRONG: repairTruncatedJson on a degraded candidate may "win"
for (const candidate of candidates) {
    const result = tryParseWithRepairs(candidate);
    if (result) return result;  // first success may still be truncated
}

// CORRECT: collect all successes and return the highest-scoring one
```

### ❌ Always applying `unescapeDoubleEncodedHtml`

```ts
// WRONG: this transforms normal HTML that does not need it
const html = unescapeDoubleEncodedHtml(rawHtml);

// CORRECT: fast path with a guard check
if (!html.includes('=\\"')) return html;
```

### ❌ Duplicating assembly logic in every branch

```ts
// WRONG: every catch/else branch rebuilds the result differently
// CORRECT: one shared assembleResult() function for every branch
```

### ❌ Using standard double quotes for HTML attributes inside JSON

When a prompt instructs an LLM to generate HTML inside JSON, enforce **single quotes** for all HTML attributes:

```
// In the system prompt:
Use single quotes for ALL HTML attributes.
WRONG: <html lang="it">
RIGHT: <html lang='it'>
```

This prevents most HTML-in-JSON escaping problems at the source.

## Recommended execution sequence

```
Raw LLM input
    │
    ├─1─ trim()
    ├─2─ fence strip (string ops + regex fallback)
    ├─3─ repairStrayGtBetweenFields (for token-artifact models)
    ├─4─ pre-repair: repairInvalidJsonEscapes(repairPrematureStringTermination(repairInvalidJsonEscapes(raw)))
    │
    ├─ Generate deduplicated candidates:
    │     [ stripped, fenceMatch, extractFirstJsonObject(raw),
    │       extractFirstJsonObject(preRepaired), extractFirstJsonObject(stripped),
    │       gtRepaired, extractFirstJsonObject(gtRepaired) ]
    │
    ├─ For each candidate, apply strategies:
    │     1. JSON.parse(candidate)
    │     2. JSON.parse(repairInvalidJsonEscapes(candidate))
    │     3. JSON.parse(repairInvalidJsonEscapes(repairPrematureStringTermination(repairInvalidJsonEscapes(candidate))))
    │     4. JSON.parse(repairTruncatedJson(repairInvalidJsonEscapes(candidate)))
    │     5. JSON.parse(jsonrepair(candidate))
    │
    ├─ Collect all valid results → choose the best by score
    │
    ├─ Post-parse:
    │     unescapeDoubleEncodedHtml(html)
    │     normalizeHtmlArtifact(html)
    │     normalizeArtifactCssJs(css, "css")
    │     normalizeArtifactCssJs(js, "js")
    │     extractArtifactsFromHtml(html)  ← only if css/js are empty
    │
    └─ assembleResult() → validated canonical output
```
